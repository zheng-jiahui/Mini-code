# MiniCode 演示视频脚本（约 2 分钟）

> 目标：一镜到底展示「空目录 → 写脚本 → 运行报错 → 自行定位修复 → finish 总结」，
> 顺带露出 `/stats` 成本面板。演示用真实 API（或 `python run.py --mock -t "..."` 离线录制均可）。

---

## 0:00–0:15 开场（项目定位）
**画面**：终端标题 + 一行字幕「MiniCode · 不依赖任何 Agent 框架的编程智能体」。
**旁白**：
> 这是一个完全不依赖 LangChain、AutoGen 这类框架的编程智能体。它只用一行 OpenAI 兼容的
> 聊天接口，历史管理、工具执行、循环控制全部自己写。今天用一个真实任务演示它是怎么干活的。

## 0:15–0:30 启动与下达任务
**画面**：敲 `python run.py -t "写一个除法函数 div(a,b)，运行验证，再补一个会触发错误的边界用例"`。
**旁白**：
> 启动后，它会在 workplace/ 下按任务名建一个文件夹，沙箱、工具、备份都自动就位。
> 我直接把自然语言任务丢给它。

## 0:30–0:55 写文件 + 运行（正常路径）
**画面**：模型正文逐字流出（流式输出），随后调用 `write_file` 写出 div 函数、
`run_command` 跑 `python calc.py`。
**旁白**：
> 注意模型的话是**一个字一个字实时打出来的**——流式输出，长任务不用盯着黑屏干等。
> 它先写文件，然后立刻用 `run_command` 真实运行验证——不是"写完就收工"，
> 系统强制它先验证再结束（假完成拦截）。

## 0:55–1:15 故意制造错误 → 自修复定位
**画面**：模型写了一个会触发 `ZeroDivisionError` 的边界用例并运行，红色报错出现。
**旁白**：
> 现在出错。关键点来了：它没有把整段 traceback 原样丢回给我，
> 而是自动解析出「出错文件:行号」，并把那一行附近的源码直接喂回给模型——
> 省掉了它再多一轮 read_file 才能看到出错位置。这就是自修复闭环的"感知层"。

## 1:15–1:35 修复 → 跑通 → finish
**画面**：模型用 `edit_block` 精准改掉那一行（不是重写整个文件），再次运行变绿，调用 `finish` 给出总结。
**旁白**：
> 模型用 `edit_block` 只改出错的那一行，再次运行通过，最后主动 `finish` 给出总结。
> 如果连续修不好，它还会提醒考虑 `rollback` 回到上一次能跑通的快照。

## 1:35–2:00 /stats 成本与耗时面板 + 收尾
**画面**：输入 `/stats`，终端打印真实 token 消耗、**时间去向**、各工具耗时占比、压缩次数。
**旁白**：
> 最后 `/stats` 看这次会话的真实成本：token 来自 API 实际返回的 usage，不是拍脑袋估算。
> 更关键的是「时间去向」——等模型通常占九成，工具执行只有个位数。
> 所以优化方向是**减少轮数和上下文长度**，而不是让工具跑得更快；
> 这也正是为什么要做上下文治理。整套能力零框架、可回滚、可观测。
> 代码与提交历史已开源，感谢观看。

> ⚠️ **旧版旁白不要再用**：早期脚本里有一句"还能看到 run_command 占了大部分耗时"，
> 与面板实测结论**矛盾**（实测等模型约 94%、工具执行约 5%，面板会直接写出
> "瓶颈在模型调用"）。照旧稿念会出现旁白和画面互相打脸。

## 录制提示
- 用真实端点录制时，把 `NSCC_API_KEY` 设进环境变量，别写进会被录屏拍到的配置文件。
- 若追求稳定不出意外，用 `python run.py --mock -t "..."` 走内置脚本，流程一致且无网络依赖。
- 字幕用中文；关键术语（edit_block / rollback / 假完成拦截 / 自修复闭环）可加高亮。
- **流式输出默认已开启**（`config.yaml` 的 `agent.stream`）。录屏时若想回到"一次性吐出"，
  把它改成 `false` 即可；网关不支持流式时它会自动退回整包，不会失败。
- 想再露一手的话，`/diff` 可以打出本次会话所有改动的 unified diff —— 这是"改了什么"
  对人和对模型都透明的关键一环，V5 的项目画像（自动识别语言/测试命令）也会在启动时注入。
